- 2026-08-13-world-persistence · 2026-08-14 · high · persistence, save-format, postcard, atomic-replace, block-identity, definition-hash, untrusted-input, allocation-bounds, supply-chain, ADR-016, mc-world, mc-sim, mc-client · A world that survives quitting: a `VoxelWorld` and the player's place in it written to `saves/world.mcw` and read back whole, with break-and-place edits intact and the player standing where they left off. A save is **one plain file replaced atomically** — sibling staging file, `sync_all`, `fs::rename` — holding a 30-byte hand-read preamble then two successive `postcard` values, the block-name table and the world. The preamble is hand-read for exactly one reason: **the version must be read before anything it governs**, so a build that cannot read a format never reports a complaint about bytes it was never entitled to interpret; version 1 is numbered 1 so an all-zero buffer declares an *unrecognised* version rather than the supported one. The table and world are two top-level values and not one struct, which is what makes "report what this save needs without reading its chunk data" true rather than aspirational. **ADR-016 was derived twice, and the second derivation is the one worth reading.** `bincode` won the first, then `cargo deny` failed on RUSTSEC-2025-0141 — development ceased *permanently* after a harassment incident, "no safe upgrade available" — and it was **removed rather than suppressed**, because no save had shipped and no world existed, so removal was a same-day refactor where suppression would have left an unfixable crate defining every byte the feature writes. The first evaluation ranked candidates on streaming, allocation bounds and `serde` and **had no maintenance criterion at all**; that omission is the whole lesson, and the criterion is now recorded in the ADR. The swap cost **four files, five call sites and zero tests** — the confinement rule (`postcard::` nameable only inside `mc_world::persistence`, every decode error collapsing to one variant at its edge) is what turned a supply-chain failure into a local event, and it is named as the mitigation it turned out to be rather than the style preference it reads as. **The security properties are the expensive knowledge and are shaped by one fact: `postcard` bounds *bytes read*, not memory.** A length prefix drives no allocation ahead of the elements arriving, but a small file still expands — `size_of::<ColumnRecord>()` against a one-byte minimum encoding is 24×, ~48× with `Vec` slack, **measured against crafted input rather than estimated**. The 16 MiB file-length precheck against `File::metadata()` is therefore the *only* thing converting a read bound into a memory bound (~768 MiB peak on a maximally hostile file, 4× the largest legitimate save), so raising it means redoing the amplification arithmetic and never just picking a bigger number. The 256-byte name ceiling is the decoder's scratch buffer and is per-field **only because the DTOs hold owned `String`s**: a `String` reads into the scratch *without advancing* it, a borrowed `&str` decodes through a path that *does*, which would silently turn a per-name ceiling into a cumulative budget with no compiler error and no failing test — **a trap for whoever next adds a field**. The line is drawn at the library: it decodes and is treated as working, we validate everything after, and no test asserts a `postcard` variant or message. **Three outcomes, not two, and the asymmetry is the argument**: a *missing* block is a hard refusal no acceptance can override, because nothing can go in the cell and that is not a judgement a player is positioned to make; a *changed* block (declared behaviour, compared by a stored 64-bit hash) is the player's decision, carried in MVP 1 by `--load-changed-blocks` and by `Acceptance`, an enum with no `Default` so the decision cannot be made by forgetting an argument; an *appearance-only* change loads without asking. Behaviour and appearance are hashed separately because one value for both would make a retextured mod indistinguishable from a rebalanced one, and the only safe response to that ambiguity is prompting on every texture edit — which trains a player to accept without reading. **No unknown-block placeholder is built, and that is decided rather than unfinished: a refusal costs a restart, a placeholder can cost a world** — it is the one option that destroys data, silently, the moment a player saves over a world whose absent blocks were substituted. `SaveNameId` is a `u32` newtype distinct from `PaletteIndex`, carried by *palette entries* and not per voxel — the mis-sizing `world-format.md` named the single highest-risk mistake persistence could make is now discharged rather than warned about. Determinism is structural: the table is a `BTreeMap` written in ascending order and **`HashMap`/`HashSet` appear nowhere in the module**, since per-instance `RandomState` would otherwise make two saves of one world differ by which hash seed a process picked. **The deliverable that outlives the format is a rule the spec produced four times at four layers: a second entry point onto a tested path is untested until something asserts through it.** Four surfaces were green under every test and held by nothing — the refusal ignoring `Acceptance`, `load_world` returning a zeroed player, the launch ignoring `Acceptance`, and `mc_sim::persistence::save` writing both a zeroed player and an empty world — each found by mutation at 140–213 passing tests, each now held by a named falsifier, three of them by exactly one. Coverage reports that the code ran; only a mutation reports whether anything was checking. **And one verification no test can perform is recorded as such: removing `sync_all()` reddens nothing**, because a flush is about surviving the machine stopping and no process that observes its own assertions afterward has stopped — held by review, deliberately, so nobody mistakes coverage for verification. Two mutations that did *not* bite were left as spec gaps rather than defects and filed separately (saving on every ending rather than only a clean close; the load-anyway hint offered even when a block is missing, where accepting cannot help). 88 scenarios, 581 tests, 94.37% line coverage, validation PASS on pass 1 with zero findings of any blocking severity · `feature/PRO-855-world-persistence`
