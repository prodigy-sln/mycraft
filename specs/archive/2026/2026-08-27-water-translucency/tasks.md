45 scenarios, each in exactly one task. Measured, not relayed: `grep -cE "^  - FR-[0-9]+\.[0-9]+-S[0-9]+: " spec.md` prints 45 and `grep -oE "^  - FR-[0-9]+\.[0-9]+-S[0-9]+" spec.md | sort | uniq -d` prints nothing. Per phase: 16 · 14 · 8 · 7 = 45. **The phases are cut by what moves a committed pixel, not by requirement group**, so FR-3, FR-4, FR-5 and FR-7 each split across phases and every split is named where it happens. Rigor is `high`: a phase's tests are authored and owned by a test author who has not seen the implementation, and the implementation context never edits a test file. **T01, T03, T08 and T12 are the test author's outright**, and two of them carry scenarios rather than a dash, because Decisions 9 and 10 make the replay oracle and the whole-frame classifier **test-support deliverables** — what FR-5.1 and FR-2.3 require *is* a test instrument, and there is no production code for it to be written against. **Two non-compiling windows, each one commit wide, and both open on an implementation commit** so the assertions that follow fail on an assertion rather than on a compile error (`testing.md` §2). **Window A opens at T02 and closes at T03**: `Opacity` joins both `BlockDefinition` and `ResolvedBlock`, neither of which has a `Default`, so every literal of either breaks at once — measured with `grep -rn "BlockDefinition {" --include=*.rs crates/ | grep -v "pub struct"` (**23** across 20 files) and the same command for `ResolvedBlock {` (**11** across 8 files), giving **31 test-owned constructions across 22 files** beside exactly **three that are not the test author's**: `crates/mc-world/src/content/luau_declaration/mod.rs:190`, `crates/mc-sim/src/content.rs:162`, and the bench at `crates/mc-world/benches/support/fixtures.rs:221`. **Window B opens at T07 and closes at T08** and is far smaller: `Vertex {` and `SectionRecord {` give **three test-owned sites in two files** — `crates/mc-render/src/geometry/vertex_test.rs:49` and `:87`, and `crates/mc-render/src/camera_test.rs:176`. **While the tree does not compile the gate cannot run**, so whoever authors tests inside either window runs **both** `cargo fmt --all -- --check` (which needs no compilable tree) and `cargo clippy --workspace --all-targets --all-features -- -D warnings` at that severity: clippy is blind to formatting, and a green suite is no evidence about a lint.

**Why phases 2 and 3 are two phases and not one.** The gate runs `cargo llvm-cov nextest --workspace` (`scripts/sdd-gate.ps1:460`), which includes `mc-client --test terrain_goldens` and `--test hud_goldens`, so anything moving a committed pixel leaves the gate red until the set is re-minted. **The renderer rework moves none of them**: with no shipped block declaring `opacity < 1.0` the translucent partition is empty, the second draw's index count is zero, and the fragment's `texel.a * 1.0` is `texel.a`. So phase 2 lands the vertex field, the partition, both pipelines, both draws and both shaders, and **ends by verifying the committed `r4` goldens still pass with `MYCRAFT_UPDATE_GOLDENS` unset** (T11). That reading is stronger than the subset check Decision 4 asks for — it isolates the machinery from the content change instead of grading them together — and costs nothing, because it is a *verification* rather than a mint and so adds no exposure to the one failure the golden procedure exists to prevent. Phase 3 is then the gate-atomic unit: `water.luau`, `SCENE_REVISION` `r4` → `r5`, one delete-and-mint. **The one-re-shoot bound is not in tension with that split**, because it is *"a statement about what `main` carries and what a later spec must not redo, not a budget on in-branch corrections"* and a spec branch squashes (`docs/technical/rendering.md:1509-1512`).

**Five constraints every test author's brief must carry**, because each bites only when a fixture is written. (a) **A blend expectation is computed in linear light and re-encoded** — the attachment is `Rgba8UnormSrgb` and the hardware blends after decoding; at a `0.25`/`0.75` split the sRGB-byte answer is wrong by 8.51, 17.57 and 21.40 code values (`architecture.md` A2). Every tolerance is stated in ΔE and derived from **both** directions — floor ≈ **4.3** (texel spread 3.16 + ordering residual ≤ 0.79 + quantisation < 0.3), ceiling **25.34** at `base:stone` — and **never loosened until green** (R1). (b) **The oracle composes per translucent *run*, never per voxel**: it marches voxel by voxel (`oracle.rs:474`) and a naive second rule predicts ten layers through ten cells of sea where one face is drawn, which reads exactly like a renderer defect (R2). (c) **FR-4.2-S2's positive control is a synthetic frame**, because the engine cannot draw a seam — `sweep.rs:281-289` states the rule and F3 defers the field that would override it. (d) **FR-4.3-S1 may not be written as "zero water fragments from a wet camera"**: the run the eye stands in contributes none, but a further run along the ray still draws its entry face and blends. (e) **Every absence assertion is an enumerated verdict** — the FR-2.3 classifier answers `EveryPixelAccounted` or a named disagreement and reports how many pixels it looked at, never `assert!(strays.is_empty())` (Decision 10).
